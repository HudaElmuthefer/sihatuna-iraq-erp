## 🚀 تشغيل النظام

### الطريقة السريعة (موصى بها)
```
انقر مرتين على: start-all.bat
```
يشغّل الخادم والواجهة معاً تلقائياً.

---

### الطريقة اليدوية

**الخطوة 1 — الخادم (Backend):**
```
انقر مرتين على: start-backend.bat
```
ابقِ هذه النافذة مفتوحة.

**الخطوة 2 — الواجهة (Frontend):**
```
انقر مرتين على: start-frontend.bat
```
يفتح المتصفح تلقائياً على: **http://localhost:3000**

---

### تشغيل يدوي من Command Prompt

```cmd
:: Backend
cd backend
npm install
node server.js

:: Frontend (نافذة منفصلة)
cd frontend
npm install
npm start
```

## 💳 تخزين بيانات بوابات الدفع الحقيقية

**مكان تخزين بيانات بوابات الدفع (زين كاش، فاست باي، كي كارد، PayPal...) هو الملف:**

```
backend/.env
```

هذا الملف غير موجود بالمشروع افتراضياً (لأسباب أمنية) — أول مرة تشتغلين:

1. انسخي `backend/.env.example` وسمّيه `backend/.env`
2. افتحيه بأي محرر نصوص، وشوفي القسم المكتوب فوقه:
   ```
   💳 اكتب بيانات بوابة الدفع هنا
   ```
3. حطي بيانات كل بوابة (Merchant ID, API Key...) اللي تحصلين عليها من حساب التاجر الخاص بيج مع كل مزود، بالسطر المقابل
4. اتركي فاضي أي بوابة ما تستخدمينها
5. أعيدي تشغيل الباك إند (`node server.js`) بعد أي تعديل بملف `.env`

⚠️ **لا ترفعي ملف `backend/.env` الحقيقي إلى GitHub أبداً** — فيه بيانات حساسة. الملف مذكور بـ `.gitignore` لهذا السبب. الملف المرفوع بـ GitHub هو `backend/.env.example` بس (فاضي من القيم الحقيقية).

## 🔧 حل المشاكل الشائعة

**المشكلة:** المنفذ 3000 أو 3002 مشغول
```cmd
netstat -ano | findstr :3000
taskkill /PID [رقم_العملية] /F
```

**المشكلة:** خطأ في npm install
```cmd
npm cache clean --force
npm install
```

**المشكلة:** الصفحة لا تتحدث
```
Ctrl + Shift + R  (تحديث قسري)
```

**المشكلة:** البيانات لا تُحفظ
- البيانات محفوظة في localStorage المتصفح
- لإعادة ضبط: `F12 > Application > Local Storage > Clear All`

## 📝 ملاحظات المطور

- النظام ثنائي اللغة (عربي/إنجليزي) مع دعم RTL/LTR
- **✅ المصادقة (تسجيل الدخول) حقيقية 100%** — تمر عبر الباك إند الفعلي (JWT + bcrypt)، **لازم الباك إند يكون شغّال** (`start-backend.bat`) قبل تسجيل الدخول، وإلا يطلع تنبيه واضح يطلب تشغيله
- **✅ النظام مربوط بالكامل بالباك إند الحقيقي — كل الموديولات بدون استثناء**: كل الوحدات السريرية والإدارية والمالية والإسعاف وCRM والفوترة **وحتى إدارة مستخدمي النظام نفسها** (تشفير bcrypt حقيقي لكلمات المرور، نفس الجدول المستخدم فعلياً بتسجيل الدخول) — عبر نظام مزامنة موحّد (`SYNCED_MODULES` بملف `AppContext.js` + `useBackendLoad()`/`usePersistedTab()` بالصفحات المحلية). كل موديول يُحمّل من السيرفر عند تسجيل الدخول، وأي إضافة/تعديل/حذف تترسل تلقائياً بجانب التحديث المحلي الفوري (النظام يستمر يشتغل محلياً بدون كسر لو الباك إند متوقف)
- **⚠️ إصلاح مهم بصفحة الحسابات المالية**: كانت بياناتها **تُفقد بالكامل عند التنقل بين الصفحات** (حالة محلية غير محفوظة إطلاقاً بالكود الأصلي) — تم إصلاحها لتُحفظ بـ localStorage + تتزامن مع الباك إند
- **الوحدة الوحيدة المتبقية محلية عمداً**: إعدادات بوابات الدفع (`PaymentSettingsPage`) — لأسباب أمنية (لا يصح تخزين مفاتيح API حقيقية بمتصفح المستخدم، راجعي التحذير داخل الصفحة نفسها)
- **✅ سجل تتبع العمليات (Audit Trail)** — كل عملية إضافة/تعديل/حذف عبر الباك إند تُسجّل تلقائياً بـ `backend/data/audit-log.json` (مين سواها، شنو تغيّر، متى)، وتُعرض عبر `GET /api/audit-log` (للإدمن فقط). يشمل تسجيل محاولات الدخول الناجحة والفاشلة أيضاً
- **✅ نسخ احتياطي تلقائي** — كل ساعة، نسخة من `db.json` و`audit-log.json` تُحفظ بـ `backend/backups/` (آخر 48 نسخة). استعادة عبر `POST /api/backups/:name/restore` (إدمن فقط)
- **✅ PostgreSQL مُختبَر فعلياً** — الـ schema (`database/postgres_schema.sql`) وسكربت الهجرة (`backend/migrations/migrate-json-to-postgres.js`) جُرّبا على قاعدة PostgreSQL حقيقية ونجحا بدون أخطاء. لسا اختياريان (النظام يشتغل افتراضياً بـ `db.json`)؛ التفعيل الكامل خطوة مستقبلية عند الحاجة لحجم بيانات أكبر من عدة آلاف سجل
- متوافق مع معايير ISO 9001 (ضبط الوثائق)
- وحدة المشاريع متوافقة مع منهجية Primavera P6
- الواجهة تدعم الوضع الليلي والنهاري
