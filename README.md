## 🆕 الإعداد الأول (مرة واحدة فقط)

قبل أول تشغيل إطلاقًا على جهاز جديد، شغّل:
```
انقر مرتين على: setup.bat
```
ينفّذ تلقائيًا: يتحقق من Node.js، وينشئ `backend/.env` من القالب (مع توليد مفاتيح أمان عشوائية قوية تلقائيًا — `JWT_SECRET` و`CREDENTIALS_ENCRYPTION_KEY`)، ويثبّت حزم الباك إند والفرونت إند، ويفحص الاتصال بـ PostgreSQL.

**إذا حدث أي خلل في أي وقت لاحقًا** (تعذّر تسجيل الدخول، صفحة فارغة، رسائل خطأ غريبة)، شغّل أولاً:
```
انقر مرتين على: check-system.bat
```
يفحص لك خلال ثوانٍ: Node.js، وملف `.env`، وحزم npm، والاتصال بقاعدة البيانات، وهل الخادم/الواجهة يعملان حاليًا — ويُظهر لك بالضبط أين المشكلة قبل أن تبحث عنها يدويًا.

**إذا كنت تخطط لنشر النظام على خادم حقيقي (خارج جهازك)، راجع [`PRODUCTION.md`](./PRODUCTION.md) — دليل HTTPS تلقائي جاهز.**

## 💳 تخزين بيانات بوابات الدفع الحقيقية

**مكان تخزين بيانات بوابات الدفع (زين كاش، فاست باي، كي كارد، PayPal...) هو الملف:**

```
backend/.env
```

هذا الملف غير موجود في المشروع افتراضيًا (لأسباب أمنية) — عند أول تشغيل:

1. انسخ `backend/.env.example` وسمِّه `backend/.env`
2. افتحه بأي محرر نصوص، وانظر إلى القسم المكتوب أعلاه:
   ```
   💳 اكتب بيانات بوابة الدفع هنا
   ```
3. ضع بيانات كل بوابة (Merchant ID, API Key...) التي تحصل عليها من حساب التاجر الخاص بك مع كل مزود، في السطر المقابل
4. اترك فارغة أي بوابة لا تستخدمها
5. أعد تشغيل الباك إند (`node server.js`) بعد أي تعديل في ملف `.env`

⚠️ **لا ترفع ملف `backend/.env` الحقيقي إلى GitHub أبدًا** — فيه بيانات حساسة. الملف مذكور في `.gitignore` لهذا السبب. الملف المرفوع على GitHub هو `backend/.env.example` فقط (خالٍ من القيم الحقيقية).

## 🔧 حل المشاكل الشائعة

**الخطوة الأولى دائمًا:** شغّل `check-system.bat` — يشخّص معظم هذه المشكلات تلقائيًا خلال ثوانٍ.

**المشكلة:** تسجيل الدخول يفشل بـ"غير مصرح" رغم بيانات صحيحة، أو الصفحة فارغة بدون أي بيانات رغم وجودها فعليًا في قاعدة البيانات (جلسة عالقة)
```
1. سجّل الخروج، ثم سجّل الدخول من جديد ببيانات حسابك
2. إذا استمرت المشكلة: F12 > Application > Storage > Clear site data
   (أو Ctrl+Shift+Delete في المتصفح لمسح الكوكيز وبيانات الموقع)
3. أعد فتح التبويب من جديد وسجّل الدخول
```
يحدث هذا عادةً عندما تتراكم بيانات جلسة قديمة في المتصفح من نسخة سابقة للنظام.

**المشكلة:** `backend/.env` مفقود، أو الخادم يطبع تحذير "JWT_SECRET الافتراضي لا يزال مستخدمًا"
```
شغّل setup.bat — ينشئ الملف تلقائيًا بمفاتيح أمان عشوائية صحيحة
```

**المشكلة:** طلبات API ترجع خطأ 503 "تعذّر الاتصال بقاعدة البيانات"
```
1. تأكد أنّ خدمة PostgreSQL تعمل فعليًا على جهازك (ابحث عن "Services" في ويندوز
   وتأكد أنّ postgresql-x64-... بحالة "Running")
2. تأكد أنّ PG_HOST/PG_PORT/PG_USER/PG_PASSWORD/PG_DATABASE في ملف backend\.env
   صحيحة ومطابقة لإعداد PostgreSQL لديك فعليًا
3. شغّل check-system.bat للتأكد بالضبط من طبيعة الخطأ
```

**المشكلة:** المنفذ 3000 أو 3002 مشغول
```cmd
netstat -ano | findstr :3000
taskkill /PID [رقم_العملية] /F
```

**المشكلة:** خطأ في npm install
```cmd
npm cache clean --force
npm install
```

**المشكلة:** الصفحة لا تتحدث
```
Ctrl + Shift + R  (تحديث قسري)
```

**المشكلة:** البيانات لا تُحفظ
- البيانات محفوظة في localStorage المتصفح
- لإعادة ضبط: `F12 > Application > Local Storage > Clear All`

## 📝 ملاحظات المطور

- النظام ثنائي اللغة (عربي/إنجليزي) مع دعم RTL/LTR
- **✅ المصادقة (تسجيل الدخول) حقيقية 100%** — تمر عبر الباك إند الفعلي (JWT + bcrypt)، ويجب أن يكون الخادم يعمل (`start-backend.bat`) قبل تسجيل الدخول، وإلا ظهر تنبيه واضح يطلب تشغيله
- **✅ النظام مربوط بالكامل بالباك إند الحقيقي — كل الموديولات بدون استثناء**: كل الوحدات السريرية والإدارية والمالية والإسعاف وCRM والفوترة **وحتى إدارة مستخدمي النظام نفسها** (تشفير bcrypt حقيقي لكلمات المرور، نفس الجدول المستخدم فعليًا في تسجيل الدخول) — عبر نظام مزامنة موحّد (`SYNCED_MODULES` في ملف `AppContext.js` + `useBackendLoad()`/`usePersistedTab()` في الصفحات المحلية). كل موديول يُحمَّل من السيرفر عند تسجيل الدخول، وأي إضافة أو تعديل أو حذف تُرسَل تلقائيًا إلى جانب التحديث المحلي الفوري (يستمر النظام في العمل محليًا دون تعطّل إذا كان الخادم متوقفًا)
- **⚠️ إصلاح مهم في صفحة الحسابات المالية**: كانت بياناتها **تُفقد بالكامل عند التنقل بين الصفحات** (حالة محلية غير محفوظة إطلاقًا في الكود الأصلي) — تم إصلاحها لتُحفظ في localStorage وتتزامن مع الباك إند
- **الوحدة الوحيدة التي تبقى بيانات اعتمادها الفعلية لدى بوابة الدفع نفسها**: بيانات اعتماد بوابات الدفع (API keys) تُشفَّر وتُخزَّن في قاعدة PostgreSQL (`CREDENTIALS_ENCRYPTION_KEY` في ملف `.env`)، وليس في متصفح المستخدم — راجع `PaymentSettingsPage` للاطلاع على تفاصيل التفعيل
- **✅ سجل تتبع العمليات (Audit Trail)** — كل عملية إضافة أو تعديل أو حذف عبر الباك إند تُسجَّل تلقائيًا في `backend/data/audit-log.json` (من نفّذها، وما الذي تغيّر، ومتى)، وتُعرض عبر `GET /api/audit-log` (للإدمن فقط). يشمل تسجيل محاولات الدخول الناجحة والفاشلة أيضًا
- **✅ نسخ احتياطي تلقائي** — كل ساعة، تُحفظ نسخة من `db.json` و`audit-log.json` في `backend/backups/` (آخر 48 نسخة). الاستعادة عبر `POST /api/backups/:name/restore` (إدمن فقط)
- **✅ PostgreSQL هو المخزن الأساسي الآن** — كل الموديولات السريرية والإدارية والمالية (المرضى، الأطباء، المواعيد، المخزون، الحسابات، CRM...، 41 موديول بالمجموع) تعمل فعليًا على PostgreSQL، وليس `db.json` (الذي بقي فقط لتسجيل الدخول/المستخدمين/سجل التدقيق). `check-system.bat` يفحص هذا الاتصال تلقائيًا
- متوافق مع معايير ISO 9001 (ضبط الوثائق)
- وحدة المشاريع متوافقة مع منهجية Primavera P6
- الواجهة تدعم الوضع الليلي والنهاري
